자녀 계정이 자기 지갑 잔액을 직접 바꿀 수 있어요

쉽게 말하면

자녀 앱에는 잔액을 고치는 버튼이 없지만, 앱이 쓰는 공개 키와 자녀 로그인 토큰이면 지갑 표에 직접 '잔액 = 100만 원'을 보낼 수 있습니다.

지갑 표의 수정 규칙이 "본인 지갑이면 수정 가능"으로만 되어 있고, 어떤 칸을 고칠 수 있는지는 막지 않았기 때문입니다.

어떤 피해가 생기나요
잔액·이자·미리쓰기 한도가 실제 거래와 어긋나요.

정산과 카드 충전이 이 잔액을 믿고 움직이면 실제 돈 문제로 번집니다.

왜 긴급인가요
로그인한 자녀 누구나, 몇 분이면 돼요.

부모가 믿고 쓰는 금융 기록이라 신뢰에 바로 닿습니다.

재현 방법

  1. 스테이징에 점검용 부모 1, 자녀 A·B 계정을 만들고 자녀 A에게 용돈 5,000원을 지급합니다.
  2. 자녀 A로 로그인해 토큰을 받고, 아래 요청을 보냅니다.
  3. 기대: 거부. 실제: 잔액이 1,000,000원으로 바뀌고 거래 내역에는 아무 기록이 없음.
재현 · 터미널 (curl)
# 자녀 A 토큰으로 자기 지갑 잔액을 직접 수정
curl -s -X PATCH "$SUPABASE_URL/rest/v1/wallets?child_id=eq.$CHILD_A" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $CHILD_A_TOKEN" \
  -H "Content-Type: application/json" -H "Prefer: return=representation" \
  -d '{"balance":1000000}'
# 결과 (예시) — HTTP 200
[{"child_id":"c-A","balance":1000000,"updated_at":"..."}]

원인

지금 정책 · supabase/migrations/…_wallets.sql
create policy wallets_update on public.wallets
  for update using (child_id = auth.uid());   -- 본인이면 모든 칸 수정 가능

고치는 방향

  1. 자녀·부모 계정에서 지갑 표의 직접 수정 권한을 뺍니다. 잔액은 화면이 아니라 거래 기록으로만 바뀌게 합니다.
  2. 용돈 지급·저축·이자·미리쓰기·상환은 DB 함수 하나씩으로 모읍니다. 함수 안에서 부모-자녀 관계를 auth.uid()로 확인하고, 거래 기록과 잔액 변경을 한 트랜잭션에서 처리합니다.
  3. 매일 1회 '거래 합계 = 잔액'을 대조하는 검사를 두고, 어긋나면 관리자에게 알립니다.

Supabase 유지 vs 별도 백엔드

"무엇이 더 좋은가"가 아니라, 지금 문제를 Supabase 안에서 고칠 수 있는지로 판단합니다. 아래 기준마다 진단에서 본 사실을 적고, 한쪽으로 기울면 이유를 남깁니다.

기준진단에서 본 것 (예시)기울기
